# 新手教学自动化复盘与可复用脚本设计

本文记录 `完整新手教学` 实机探路中遇到的问题，并把可复用动作沉淀成后续脚本的设计规则。当前实现仍以 MuMu `1280x720`、Maa `display_short_side: 720` 为基准。

## 结论

Maa pipeline 本身适合稳定执行，但不适合手写大量重复的固定点位流程。新手教学这类长线性任务应采用两层结构：

- 维护层：`scripts/golden-spatula-generate-tutorial-pipeline.mjs`，用高层片段描述点击、对话、拖拽、截图和等待。
- 运行层：`resource/pipeline/tutorial.json`，由生成脚本产出，保持 MaaFramework 可直接加载的扁平 JSON。

以后新增教程或分段对局脚本时，优先扩展生成脚本里的片段，而不是直接手写几十个 pipeline 节点。

## 本次遇到的问题

- 对话推进有两个热点：普通箭头常在 `(936,676)`，部分教程卡片需要先点 `(730,630)` 再点 `(936,644)`。只点箭头会出现卡住。
- 商店卡牌不能稳定点卡面购买，实际可靠点是价格区域。第三格常用 `(720,692)`，第二阶段更靠右的第三格需要 `(756,692)`，第四格可用 `(878,692)` 或 `(914,692)`。
- 上阵拖拽必须从真实备战席单位起手。第一次错误地拖了场上/边缘单位，后续改为 `(340,500) -> (735,388)` 才生效。
- 羁绊阶段存在多层提示：先点羁绊入口，再点效果提示，再点成员提示。跳过任一层会让后续出售动作无效。
- 出售不是点击按钮，而是拖单位到底部出售区域。多余英雄用 `(335,500) -> (640,641)`，选秀带回单位用 `(640,504) -> (579,642)`。
- 蓝色法球需要两次点击同一点：第一次推进提示，第二次移动拾取。单次点击会看似无反应。
- 装备合成需要先让教程显示拖拽提示，再从左侧装备栏拖到目标英雄。第二件装备直接拖可能不触发，要先完成提示推进。
- 选秀阶段不是直接买卡，而是点击地图目标让角色移动到目标单位附近。固定点击 `(612,394)` 可以带回一个带装备单位。
- 第五阶段升三星并非固定两次购买结束，而是需要按教程刷新节奏执行：买两张、刷新、买一张、刷新、刷新、买两张、刷新、买一张。
- 胜利页之后仍有两段完成对话，最后才回主界面。不能把点击“现在退出”当作任务终点。

## 可复用片段

### 1. 对话推进

用途：教程文本、战斗结算、最终完成提示。

生成脚本片段：`dialogPair(prefix, options)`

默认行为：

- 第一下点 `(936,676)`，等待 `700ms`。
- 第二下点 `(936,644)`，等待调用方指定时间。

变体：

- 左侧/中部教学卡片使用 `firstTarget: target.dialogueLeft`。
- 进入战斗或加载场景后，第二下等待要放大到 `25000-38000ms`。

### 2. 截图检查点

用途：关键状态落盘，方便复盘和裁剪模板。

生成脚本片段：`cap(name, filename)`

命名规则：

- `tutorial_full_00_mode_page`
- `tutorial_full_05_after_battle1`
- `tutorial_full_15_three_star`
- `tutorial_full_17_complete_lobby`

长流程至少在每次状态突变后截图：进入教学、购买后、上阵后、升星后、出售后、选秀后、三星后、胜利页、回主界面。

### 3. 固定热点点击

用途：玩法页、商店购买、刷新、法球、继续训练、最终退出。

生成脚本片段：`click(name, target, postDelay)`

建议把坐标放进 `target` 常量，不在步骤里直接散写数字。后续做模板/OCR 替换时，只改常量或 helper 即可。

### 4. 拖拽上阵

用途：备战席单位上阵、替换单位、教程棋子移动。

生成脚本片段：`swipe(name, begin, end, duration, postDelay)`

当前稳定坐标：

- 初始上阵：`[340,500] -> [735,388]`
- 激活羁绊：`[337,496] -> [640,282]`

后续优化方向：在拖拽前用模板/OCR 检查人口、备战席单位高亮和目标格高亮。

### 5. 出售单位

用途：回收金币或装备。

当前稳定坐标：

- 阶段 3 多余英雄：`[335,500] -> [640,641]`
- 阶段 4 选秀带回单位：`[640,504] -> [579,642]`

出售片段风险高，必须只在教程专用脚本里使用。常规对局脚本应先引入识别保护，再考虑开放。

### 6. 装备拖拽

用途：基础装穿戴与合成。

当前稳定坐标：

- 第一件：`[102,104] -> [708,369]`
- 第二件合成：`[102,101] -> [708,369]`

后续优化方向：装备栏 ROI、目标英雄高亮 ROI、装备图标模板三者同时确认。

### 7. 商店购买与刷新

用途：教程升星、三星。

当前稳定点：

- 第三格价格：`[720,692]`
- 第二阶段第三格偏右价格：`[756,692]`
- 第四格价格：`[878,692]` / `[914,692]`
- 刷新按钮：`[247,684]`

后续优化方向：用商店头像模板识别目标棋子，再用卡位价格热点点击；不要在普通对局里用无识别固定 D 牌。

## Pipeline 组织规则

- 入口任务命名使用业务名，例如 `BeginnerTutorialFullRun`。
- Maa 节点按模块前缀命名，例如 `Tutorial_Stage3DragGuard`、`Tutorial_Stage5RefreshD`。
- 生成脚本 helper 使用通用动词：`cap`、`click`、`swipe`、`dialogPair`。
- `tutorial.json` 视为生成物；可读但不建议手改。
- `main.json` 保留主界面、日常、巡检和调试任务；教程长流程放在独立 `tutorial.json`。

## 下一步优化顺序

1. 给关键阶段加轻量守卫：玩法页、新手教学页、商店打开、羁绊面板、胜利页。
2. 把固定等待替换成 `TemplateMatch` 等待：战斗结束、商店出现、三星动画结束。
3. 把商店购买点从固定槽位升级为“模板命中目标棋子后点击同槽价格区”。
4. 把装备拖拽升级为“装备图标 + 目标英雄高亮”双确认。
5. 把教程脚本拆出分段入口：从阶段 1、阶段 2、阶段 3、阶段 4、阶段 5 继续跑，方便失败后复测。

## 常用命令

```powershell
pnpm golden:generate-tutorial
pnpm golden:generate-tutorial:check
pnpm prepare:golden-spatula-mumu
pnpm golden:tutorial
pnpm golden:red-dot -- --entry Tutorial_CompleteLobbyScreencap --timeout-ms 60000 --no-strict-patrol-coverage
```

`pnpm golden:tutorial` 只适合账号仍能进入新手教学的状态。若账号已经完成教学，优先使用截图节点或后续新增的阶段续跑入口验证资源加载。
